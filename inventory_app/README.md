# 菜騎鴨庫存管理

正式店務使用 [雲端庫存系統](https://duck-inventory-953640890149.asia-southeast1.run.app/)，以授權的 Google 帳號登入。

本機開發版可雙擊 **啟動庫存管理.cmd**，網址為 http://127.0.0.1:8765 。未配置 Google 登入時，初次建立至少 10 個字元的管理密碼。雲端與本機資料各自獨立，不能同時當作正式庫存使用。

## Windows 可攜式交付

正式搬家包放在專案根目錄的 `output/portable-release`（不提交 Git）。ZIP 解壓縮後雙擊「啟動庫存管理.cmd」，使用隨包提供的 Python 3.12 x64，不需要安裝 Python。支援 Windows 10/11 的 Intel/AMD 64 位元電腦。第一次由收件者自行建立本機密碼，程式只監聽 127.0.0.1。

交付包包含一致時間點的雲端資料快照、照片、價目表範本與搬家驗證清單；不包含雲端金鑰、原密碼或 Google 登入綁定。快照時間見包內 `migration-report.json` 與 `使用說明.txt`。快照之後的雲端修改不會同步，正式切換後只能選定一份系統記錄庫存。

「停止庫存管理.cmd」會等待進行中的備份及 Excel 同步完成；「還原本機備份.cmd」將本機備份還原到新的 `restored-*` 資料夾並切換使用，保留原資料。請保留整份資料夾，尤其 `data`、`templates`、`restored-*` 及 `portable-data.json`。關閉瀏覽器不等於停止背景程式。

維護者以 `tools/build_portable.py` 的明確來源參數建立新的交付目錄：`--runtime` 指向可搬移的 CPython 3.12 Windows x64 執行環境，`--packages` 指向已驗證套件，`--seed` 指向已核對的資料快照（含 data、templates、migration-report.json），`--destination` 必須是尚不存在的路徑。此工具不會自行連線或複製雲端憑證。打包後必須在獨立解壓縮目錄驗證啟動、資料寫入、Excel 與備份還原；不要把測試寫入的資料當作交付資料。

## 初次匯入

1. 點「設定 → 匯入原始 Excel」。來源優先使用專案根目錄的 `raw_data` 資料夾，沒有此資料夾時才使用舊的 `原始資料`。
2. 預覽資料，將同品號但不同商品的品號改為不重複的值，再確認匯入。相同商品的不同效期會保留為不同批次。
3. 空白庫存保留「未盤點」，空白價格保留「未設定」。價格未填不能匯出成零元。
4. 到「商品對應」確認價目圖卡與發票商品各自對應哪項商品；不同包裝可保留原價，只連動缺貨。

匯入只接受空資料庫；重複確認同次匯入不會建立第二份庫存。原始 Excel 全程唯讀。

## 日常使用

商品依原有分類順序排列，同分類內有照片的優先。缺圖或照片載入失敗時，顯示 `product-no-photo-light.png` 菜騎鴨預設圖；預設圖不會被算作商品實拍照片。每日銷售單可搜尋與篩選全部庫存商品；店家庫存及價目表保留分頁操作。

導覽固定在側邊／手機底部，內容區可捲動。價目表預設每頁 24 項，可選 12／48 項，提供有照片／尚無照片篩選；點照片可放大。進貨、出貨、盤點按鈕分別為綠、藍、琥珀色，紅色表示異常或具風險的操作，均搭配文字。

- **每日銷售單（首頁／第一頁籤）**：選商品、填數量，結帳後一次扣庫存。
- **管商品（第二頁籤）**：預設開啟「盤點庫存」。切換「商品資料」可查看照片、品名、售價與可售庫存；可搜尋及篩選待補貨、未盤點或即期。
- 點商品開啟管理面板，再執行進貨、店內賣出、盤點或修改售價；批次進價、效期及異動紀錄按需展開。
- **盤點庫存**：商品照片卡直接顯示各效期批次，點大顆「＋／−」或輸入實際數量。「數量沒變」快速確認，「已售完，填0」明確登記零庫存，「清除此筆」則取消這次填寫。底部固定的儲存列顯示已填筆數。空白不更動、0 表示沒有庫存；帳面數量包含訂單預留，不等同可售數量。跨頁／分類／模式切換會保留已填草稿，儲存按鈕一次提交全部已填列（最多 200 批）。任何一列版本衝突或侵占預留都會整批取消寫入；錯誤後保留輸入。重新載入前會提醒未儲存內容，草稿不跨瀏覽器重啟保存。
- 集中盤點只改數量；效期未知或尚未確認可售的批次，仍須點「效期／狀態」確認。版本衝突時可點「重填發生衝突的這一批」重新讀取該批數量，其他草稿會保留。
- **每日銷售單**：每天結帳後，選商品、填整天賣出數量，預覽後一次扣庫存；下方可查看已送出的單與沖銷。
- **匯出資料**：預覽／列印價目表，或檢查後匯出發票平台用的七欄商品 Excel。產生檔案後仍需自行上傳發票平台。
- **設定**：集中放置 Excel 匯入、備份、價目表／發票商品對應、完整異動紀錄與庫存總覽。誤登進出貨可在紀錄沖銷，已盤點過的舊紀錄使用新的盤點更正。
- 新商品可在「設定 → 發票商品對應 → 新增發票商品」加入，分類編號與是否含稅依發票平台既有設定填寫。

商品對應預設只顯示待確認項目；已整理的資料可切換「查看全部／修改已整理資料」再調整。不同包裝或庫存表未列的價目卡，可選「獨立品項（不連動庫存）」保留來源售價。依來源補入的售價會記在商品異動紀錄，之後仍可直接修改。

新增商品的初始庫存為未知，請先盤點。過期與待確認可售的批次不計入可售庫存。效期未知的商品須由老闆確認可售後才能出貨；每日銷售單會將這類批次排在有日期的批次後面。

## 每日結帳扣庫存

1. 點側邊／手機底部的「每日銷售單」。
2. 選銷售日期（預設今天，可補登過去日期），搜尋商品並加入清單。
3. 填當天合計賣出的數量，以顯示的庫存單位為準。一般商品填整數，重量商品可填最多六位小數；不需輸入客人資料或售價。
4. 點「檢查整張單」，確認每項商品的賣出數量、扣後剩餘量與扣除批次，再按「確認扣庫存」。
5. 下方「每日紀錄」保留日期、備註、商品與實際扣除批次，可查看明細。

每個日期只能有一張有效單，最多 200 項商品，同商品合併為一列。系統依效期由近到遠扣除已盤點、已確認可售的批次；效期未知但已確認可售的排最後。依銷售日期判斷效期與進貨日期，補登仍從目前剩餘庫存扣除，不會重建歷史庫存。舊客人訂單的有效預留不會被扣走。

任一商品庫存不足或預覽後庫存改變，整張不扣；請先確認庫存再重試。每天只有一張有效單、重送同一請求只扣一次。送出結果因網路中斷不明時，畫面保留原送出內容並鎖定修改，按「確認上次送出結果」安全重試。

草稿儲存在目前瀏覽器分頁（sessionStorage），切換系統功能或重新整理會保留，關閉分頁後不保證保留。登出不會刪除這個分頁的銷售單草稿。

填錯可在紀錄中「沖銷整張單並加回庫存」，填原因後整張還原，再重填該日期。若其中任何批次已有後續盤點，整張沖銷會被拒絕，請用新的盤點更正；不能從一般異動紀錄單獨沖銷銷售單中的一筆。

客人下單入口與 API 預設停用，`/shop` 轉到每日銷售單登入入口。「設定 → 舊客人訂單紀錄」僅供處理既有訂單與預留；歷史資料不刪除。已透過舊訂單交付或單筆「店內賣出」扣過的商品，不要再填進每日銷售單，以免重複扣庫存。料理、購物車與接單設定已從日常入口移除。

雲端版使用 Cloud Run、Supabase PostgreSQL 與私有照片儲存；上線網址、驗收與操作方式見 [雲端部署紀錄](docs/cloud-deployment.md)。本機 SQLite 保留作開發與切換前備份，不與雲端同時接受正式寫入。

## LINE 接單

頁面分成兩步：

1. **匯入 LINE 聊天**：電腦版 LINE 打開群組 → 右上角選單 →「儲存聊天」，存成文字檔（每次存同一個位置、覆蓋舊檔即可），再把檔案拖進「LINE 接單」的框框。系統只保存上次之後的新留言，客人的文字留言交給 OpenAI 整理成訂單。第一次匯入會先詢問從哪個時間開始。
2. **選時間，核對後匯出**：按「全部／今天／昨天／自訂」。下方清單、右側「商品數量合計」都會換成這段時間；核對完按「⬇ 匯出 Excel」。

訂單清單只有「待處理」「已完成」兩個分頁，「不是訂單」放在右邊小字。待處理中，最近一次匯入的訂單排在最上面，標題為「這次匯入新增」，卡片有綠色「新」標記；其餘在「之前還沒處理」。每張卡片左邊是 AI 整理、右邊是 LINE 原文；備好按「已完成」，誤判的按「不是訂單」。

匯出的 Excel 包含選定時間內「待處理＋已完成」的訂單，依 LINE 留言時間計算（台灣時間，含結束分鐘），分成三張表：

- 商品合計：同商品同單位加總，另列沒寫數量與需確認的筆數；「不是訂單」與「取消」不計。
- 訂單明細：每個品項一列，附處理方式、載具、付款、狀態與 LINE 原文。
- 其他留言：沒變成訂單的客人留言、客人傳的圖片與收回的訊息，方便檢查有沒有漏單。

客人打的字一律存成文字，「=」開頭也不會變成 Excel 公式。要從聊天檔匯出，先把檔案拖進第 1 步（自動轉成訂單），再用第 2 步匯出。

判斷新留言不看檔名，而是在新檔中找到上次最後幾則留言的位置；檔名多了「(更新1)」也能接續。匯出檔比上次舊或找不到上次位置時會停止，不會重複建立訂單；可重新選擇開始時間，已匯入的留言自動略過。店家帳號（菜騎鴨官方小幫手、鴨老闆、小幫手）、貼圖與系統訊息不送 AI；客人傳的圖片和收回的訊息列在「最近一次匯入」提醒查看。

品項會對應店內商品（例如「豬五花」對「台灣豬五花(火)」），卡片同時顯示客人要的品項與對應商品的品號、庫存及售價；清單上沒有的生鮮蔬果保留 AI 整理的品名。LINE 訂單不會自動扣庫存，出貨後仍以每日銷售單扣庫存。

清單依留言時間排序，可切換「新到舊／舊到新」（記在這台電腦），每天一個標題。AI 無法確定的訂單會標「需確認」；按「✎ 編輯」可以對照 LINE 原文修改地點、客人、類型、每個品項（數量、單位、處理方式、對應的店內商品）和載具、付款、備註，儲存後標示「已手動修改」。已帶入每日銷售單的訂單不能修改。

### 帶入每日銷售單扣庫存

LINE 訂單按「已完成」後，到「每日銷售單」按「從 LINE 接單帶入」，或上傳 LINE 接單匯出的 Excel（可以先在 Excel 改「數量」或補「店內品號」）。核對視窗逐筆列出客人要的品項與對應的店內商品，勾「✓」的品項才會加進銷售單；店內沒有的生鮮預設不扣庫存，也可以手動選商品。單位不同（例如客人寫「包」、庫存是「斤」）會提醒換算。

帶入的訂單跟著銷售單一起送出，在同一個交易裡標成「已扣庫存」，同一筆訂單不會被帶入兩次；已扣庫存的訂單不能改回待處理。銷售單沖銷後，這些訂單可以重新帶入。

### 設定 OpenAI 金鑰

1. 到 <https://platform.openai.com/api-keys> 建立金鑰，帳戶需有 API credits。
2. 用記事本新增檔案，只貼上金鑰一行，存成 `inventory_app\data\openai-key.txt`。`data` 資料夾不進 Git，金鑰也不會放進系統備份。
3. 到「LINE 接單」按「測試連線」。放好金鑰不必重新啟動。

雲端版改用環境變數 `OPENAI_API_KEY`（存放於 Secret Manager），並先執行 `app/sql/003_line_orders.sql`、`app/sql/004_line_order_sales.sql`、`app/sql/005_line_order_edits.sql` 遷移。選填：`OPENAI_MODEL`（預設 `gpt-6-luna`）、`OPENAI_REASONING_EFFORT`、`OPENAI_BASE_URL`。頁面只顯示有沒有接上，不顯示模型與費用；每次轉換的用量仍保存在匯入紀錄供查核，送出時設定 `store: false`。

## Google 登入

後台支援指定 Google 帳號登入。系統管理員可在「設定 → 管理登入帳號」新增老闆與員工；老闆可新增及停用員工。客人下單預設停用。

需設定 `AUTH_MODE=google`、Google OAuth 用戶端、回呼網址與系統管理員 Email；啟用後原共用密碼不能登入。尚未配置的本機環境仍使用原密碼。設定步驟見 [Google 登入說明](docs/google-login.md)。

## 本機 Excel 自動同步

雲端版在「匯出資料」提供庫存管理表，以及**下載三份 Excel 備援**。下載當下從同一個 PostgreSQL 快照產生三份檔案，以 ZIP 下載到店內電腦；不是雲端自動寫入電腦資料夾。請每日結帳後下載並解壓縮，故障時以最新檔案接續盤點。價目表原照片完整保留，ZIP 約 150 MB，採串流下載。雲端暫存可隨時重建，資料與原始範本保存在 Supabase 私人儲存。Excel 的手動修改不回寫系統。

以下自動背景同步與檔案總管路徑僅適用於本機版：

「匯出資料」只提供庫存管理表下載。系統啟動，以及成功記錄銷售、沖銷、進貨、盤點、改價或修改商品對應後，會在背景產生同一批三份 Excel：

- `庫存管理.xlsx`：全部商品與批次、原庫存表前 13 欄及批次編號；未知數量或價格保留空白，庫存是批次帳面數量，包含已預留或尚未確認可售的數量。
- `商品價目表.xlsx`：沿用 `raw_data` 價目表的照片與版型，只更新已確認對應且採商品售價的儲存格，獨立包裝保留原值。
- `發票系統.xlsx`：保留七欄格式與發票平台品號、稅別及商品類型，已對應商品使用系統品名、售價及單位。

同步檔案放在 `data/excel_sync`。匯出頁顯示最後完成時間，按「複製資料夾位置」後貼到檔案總管位址列，即可取得最新同批三份檔案。每批存入新的時間戳記資料夾，三份完成才更新 `latest.json`；保留最近兩批完整結果，避免覆寫正在 Excel 開啟的檔案。舊檔不會在 Excel 中即時刷新；每次應從匯出頁開啟最新資料夾。

系統資料庫是唯一主資料，Excel 是輸出副本；直接修改 Excel 不會回寫系統。`raw_data` 原檔不被覆寫，需保留原價目表供版型使用。首次套用會用目前系統資料重建三份檔案，不會再次扣庫存。同步失敗不回滾已成功的店務操作；匯出頁顯示原因、保留上一批，修正後可按「重新同步」。電腦及系統關閉時不執行，重新啟動會補做同步。

## 備份與還原

系統運行時每天自動備份到 `backups`，啟動時補做當天尚未完成的備份。電腦關閉時不會執行。可隨時在設定點「立即備份」。備份包含資料庫、帳號密碼雜湊及已匯入圖片；原始 Excel 仍應自行保存。

備份與資料在同一台電腦，請定期另存備份 ZIP 到其他磁碟。

還原至新的空資料夾（不覆寫目前資料）：

```powershell
.venv\Scripts\python.exe run.py --restore "備份檔完整路徑.zip" --destination "新的空資料夾"
.venv\Scripts\python.exe run.py --data-dir "還原資料夾" --port 8767
```

本機版只監聽 127.0.0.1；跨裝置請使用正式 Cloud Run HTTPS 網址。

## 開發與驗證

Python 3.12。既有 `.venv` 可直接使用；重新安裝時：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe run.py
```
