# 菜騎鴨：客人選購與料理組合模式

日期：2026-10-01。設計稿；尚未實作、尚未開放下單。

## 已確認

使用者希望客人可瀏覽所有商品分類，也能按一道菜一起購買食材與調味料，解決不知道吃什麼的問題。青椒牛肉僅為使用者隨口舉例，不列為建檔需求；首輪只測試三道由現有商品組成的菜色。組合沒有折扣，總價等於實際選購的商品單價乘數量後加總。料理圖片或圖示須親切、引起食慾；維持簡約的一頁式切換，允許捲動與分頁。

交易採「送出訂單 → 店家確認 → 到店取貨付款」，第一版不串線上金流。食材與調味料以既有整包、整瓶出售，顧客可取消家裡已有的調味料。第一版採免會員購買、單店取貨，訂單需要姓名、電話與預計取貨時段；此為降低操作負擔的設計建議。

## 客人畫面

客人有獨立 `/shop` 入口，手機底部三個主入口：今天煮什麼、全部商品、購物車。店主後台保持獨立並須登入。

### 今天煮什麼

- 標題「今天想吃什麼？」與副標「選一道菜，食材一起帶回家」。
- 搜尋菜名／食材，使用少量直覺標籤：家常菜、快速上桌、孩子喜歡、湯品。標籤由店家設定，不能因圖像或文字自動判定營養、過敏或適齡。
- 大幅熟食照片或溫暖的食物插畫，搭配清楚菜名；無圖片時以盤子、鍋子與食材小圖示組合，保留菜名，不只用 emoji 讓客人猜。
- 每張料理卡顯示店家設定的建議人數、預估料理時間、實際販售包裝的合計金額，以及「選購這道菜」。人數與時間由店家核實後發布。
- 首輪測試菜色：番茄牛肉烏龍麵、照燒雞腿、玉米貢丸湯。確切商品及售價見本文「三道測試料理」。尚未盤點的必要商品會阻擋正式開放訂購，測試環境使用獨立示範庫存。

### 料理詳情

1. 上方顯示熟食圖、菜名、建議人數與簡短介紹。圖片下標示「料理示意，販售內容為下列食材」，避免誤以為購買熟食。
2. 「這次會買到」逐列顯示商品照片、名稱、包裝、購買數量與小計。主食材是此組合必要項目，組合數量以整組增減；顧客若想自選主食材，可轉往全部商品。
3. 「調味料，家裡有就不用買」逐項勾選；預設包含店家設定的必要調味商品，提供明確的「調味料家裡都有」按鈕，一次取消調味商品。油、鹽等即使常見也須列為已含商品或清楚列入自備，不宣稱未涵蓋的清單是完整備料。
4. 烹調使用量與購買包裝分開呈現。例如食譜需醬油兩匙，實際販售是一瓶，不能用兩匙的價格假裝買到一瓶。組合人數是料理建議，整包剩餘食材須說明。
5. 固定底部顯示「已選 X 項・合計 $X」與「整組加入購物車」。不展示虚構折扣、劃線原價或未含必選食材的低價。
6. 簡短料理步驟收在可展開區，不妨礙選購。若有過敏原、辣度等資訊，必須由店家依商品及配方確認後展示。

### 全部商品

- 顧客分類名稱移除 A／B 等內部代碼，呈現乳飲品、肉品海鮮、冷凍食品、火鍋料、米麵雜糧、調味醬料、調味粉、罐頭與其他。蔬菜需先建立實際商品後才顯示此分類。
- 清單涵蓋所有已上架商品，可搜尋、分類、捲動與換頁；有庫存且規格／售價已確認才能加入購物車。
- 商品卡顯示商品圖片、完整名稱、販售包裝、價格及「加入購物車」。未上架、來源有疑義的價目卡不直接向客人展示成可購商品。
- 缺貨显示「暫時售完」，未確認的商品顯示「店家確認中」；不公開成本、供應商、內部品號衝突、盤點數量或操作紀錄。

### 購物車與送單

- 以菜色分組方便檢查，單買商品另列；每列均可追溯實際商品和份量。
- 相同 SKU 在庫存計算時加總，保持菜色來源資訊。兩道菜加入相同調味料時提醒「這瓶調味料已加入，可調整數量」，由顧客確認是否只買一瓶，不自行推算一瓶一定足夠。
- 客人填姓名、電話、預計取貨時段，確認總價後按「送出訂單，等店家確認」。時段由店主設定並控制是否可選。
- 成功後显示訂單編號與「待店家確認，尚未付款」，提供無法猜測的私人查詢連結。重新整理或連點不重複建立訂單。
- 第一版不自動寄簡訊或 LINE 訊息；客人可從查詢頁看狀態，店家需要時自行聯絡。

## 視覺與互動

使用暖白底、深綠文字、自然食物照片，少量柔和橘色凸顯選購按鈕；不使用閃爍、倒數或滿版促銷。

- 橘色：選購／加入購物車；綠色：店家已確認、可取貨等成功狀態。
- 琥珀色：待店家確認、需留意的商品；紅色：缺貨阻擋、錯誤；灰色：不可操作。
- 主體文字至少 16px，主要按鈕至少 48px，高對比、按鈕明確寫動作。照片完整可見，手機兩欄商品卡、料理卡以大圖呈現，較窄畫面轉一欄。
- 圖示皆搭配文字；按鈕能用鍵盤操作，照片有替代文字，購物車更新有狀態提示。所有底部固定區域須留空間，不遮住最後一筆商品。
- 細節可由覆蓋面板查看，關閉後回到原搜尋、篩選與捲動位置。

## 店家管理

新增「料理組合」與「客人訂單」兩項管理功能。

建立料理只需填菜名、圖片／圖示、建議人數、時間與簡短介紹，再從既有商品選食材和調味料、數量。清單分為主食材和可取消的調味料；售價自動相加，沒有另一套組合售價。可先存草稿，再預覽客人畫面與發布；缺少商品、包裝或售價時禁止發布可購組合。

訂單狀態：待確認 → 已確認 → 可取貨 → 已取貨，另有取消／拒絕。店家能查看按商品彙整的備貨清單與原菜色分組。第一版不加入配送、會員積分、優惠券或金流。

## 庫存及價格規則

- 料理是既有商品的組合關係，沒有獨立的一套庫存。料理可售份數受所有已選必要商品的可用量限制。
- 不將待盤點、過期、未確認可售或缺價的商品作為立即可購庫存。尚未建檔的食材不能以替代品價格或蔬菜金額系列充當。
- 客人送單時重新檢查商品／價格／可用量並保存訂單快照；價格或缺貨有變，先回傳差異讓客人確認，不悄悄調整金額。
- 待確認訂單不預留，畫面明示須等店家確認。店家確認時在同一筆資料庫交易中檢查并預留可售批次；確認不足就整筆失敗，要求店家處理。
- 可下單量＝可售庫存減有效預留。現有店內銷售、盤點與批次操作也必須檢查預留，不能只在顧客 API 扣除。
- 領貨時將預留轉為一次實際出庫；取消釋放預留。逾時取貨以店家在訂單上確認的期限為準，期限後釋放可由可靠排程或交易前清理執行，不依賴瀏覽器保持開啟。
- 若批次在取貨前到期，不能交付；店家需換成有效批次或聯絡取消。組合發布與訂單確認也須考量預計取貨時間。
- 第一版料理使用已確認的固定包裝數量；秤重商品僅在店家設定可售份量及計價方式後納入，不用未知重量宣稱確定總价。

## 資料與介面邊界

沿用 products、batches、movements；新增以下資料：

| 資料 | 用途 |
| --- | --- |
| storefront_products | 上架狀態、客人分類、展示名稱、已確認販售包裝 |
| recipes / recipe_items | 菜色、圖片、標籤、建議人數、步骤、引用商品、份量及主料／調味角色 |
| orders / order_items / order_groups | 訂單狀態、聯絡資料、取貨時間、商品與價格快照、菜色來源、冪等識別 |
| reservations | 訂單對批次的預留、數量、期限及狀態 |
| order_events | 確認、取消、取貨等操作者與時間 |

新增專用客人只讀商品／菜色 API 及送單／私人查詢 API。現有後台 API 保持登入權限，不能為了顧客模式直接公開 `/api/products` 或 `/api/meta`。公開圖片須限制在已上架商品與菜色，資料庫／Storage 管理金鑰只留後端。

私人查詢 token 採高熵值，資料庫保存其雜湊；不可憑流水號或電話猜取別人的訂單。送單有驗證、長度與數量限制、持久化限流及重複請求防護。聯絡資料不寫入公開頁面或一般存取日誌。

雲端部署沿用已選 Cloud Run＋Supabase 方向；訂單交易與預留必須在實際 PostgreSQL 上驗證。若先以本機開發展示，僅測試用途，`127.0.0.1` 不是能傳給顧客的公開網址。

## 驗收與資料前提

測試單品／組合價格一致、取消調味料重算、同商品跨菜色加總、缺料阻擋、連點只送一單、兩張訂單競爭同批庫存、店內銷售與預留競爭、取消釋放、領貨僅扣一次、價格變更重新確認、過期批次不交付、後台敏感資料無法從客人端讀取。

畫面驗證涵蓋桌機及手機、長品名、無照片、所有商品分頁、返回保留位置、鍵盤操作、字體放大及固定購物車不遮內容。

正式發布前由店家確認三道菜的實際烹調份量、圖片與料理資訊。既有待對應價目卡也不能視為已可購商品。本設計尚未改動資料庫或建立實際顧客訂單。


## 三道測試料理（2026-10-01 依目前資料庫核對）

價格均為原始庫存表匯入的整包／整瓶售價，不是吃一份的成本；所有金額在實作時由商品主檔動態加總，不寫死到料理售價欄位。購買量一律為下列商品各一個販售單位，烹調依所需量使用，剩餘原料可留作下次料理。

| 菜色／首頁情境 | 商品代碼 | 商品與購買量 | 單價 | 角色 |
| --- | --- | --- | --- | --- |

| 同上 | C15001 | 讚岐烏龍麵240g，1包 | 135 | 主食材 |
| 🍗 照燒雞腿／想吃下飯菜 | B10006 | 六兩無骨雞腿，1包 | 150 | 主食材 |
| 同上 | F07001 | 甘露醬油1000ml，1瓶 | 55 | 可取消的調味料 |
| 同上 | F07003 | 萬家香味醂450ml，1瓶 | 55 | 可取消的調味料 |
| 🍲 玉米貢丸湯／想喝暖湯 | J03001 | 牛頭牌玉米粒，1罐 | 35 | 主食材 |

| 同上 | H99004 | 康寶雞湯塊，1盒 | 45 | 可取消的調味料 |

- 番茄牛肉烏龍麵：110＋135＝245 元。使用現有調理湯包，不額外加入資料表沒有的番茄或蔬菜。烏龍麵每包實際內含份數須由店家確認，不把品名中的240g當成整個售價包裝重量。
- 照燒雞腿：150＋55＋55＝260 元；已有醬油和味醂而取消兩項後為150元。配飯是食用建議，米飯不包含在此組合；視烹調方式需自備少量食用油，頁面須顯示此項，不能在圖片暗示連白飯都包含。
- 玉米貢丸湯：35＋180＋45＝260 元；取消家裡已有的雞湯塊後為215元。用水及調味濃度按商品標示和店家確認的簡短做法呈現。

三張菜色圖只呈現所包含的主要食材，不加清單沒有的青菜、蛋或蔥來暗示販售內容。圖片可先採簡單料理插畫／icon，保留「料理示意」文字。建議人數、烹調時間和精確食譜比例須在測試確認後再填，不為美觀杜撰。

目前番茄牛肉湯、雞腿與玉米粒的庫存為未盤點；其餘五項有已知可售量。本輪可測試選菜、調味料取消、合計和購物車互動，正式下單功能仍須遵守庫存驗證，不能把未知庫存補成可售。

首頁先只顯示這三道料理，以「快速上桌／下飯主菜／暖心湯品」幫助選擇，並提供「幫我挑一道」按鈕。正式模式只從當下可購的料理挑选；若沒有可購料理，顯示店家確認中，不隨機推出缺料組合。第一版使用簡單篩選和隨機選擇即可，不需要外部 AI 服務。
